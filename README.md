# tender-rag · 招投标文件智能问答

面向招投标场景的文档问答系统：输入招标/投标文件（复杂表格 + 图文混排 + 部分扫描件），
输出带引用溯源的精确答案（资质要求、评分办法、保证金、关键条款等）。

**这不是一个 demo，是一个有评测报告、可部署、有性能数据的生产级系统。**

## 为什么做这个

- 数据脏且真实：招投标文件是典型的"表格 + 条款混合"文档，解析是最大技术挑战
- 答案可验证：资质等级、保证金比例、开标时间等都有确定答案，golden set 好构造
- 业务痛点真实：标书制作人员需要快速定位上百页文件中的硬性要求

## 架构

```
PDF/扫描件 ──► 解析层(pdfplumber/PyMuPDF + 版面分析模型) ──► 结构化切分
                                                          │
用户提问 ──► 查询改写 ──┬─► BM25 关键词检索 ──┐            ▼
                       └─► bge-m3 向量检索 ───┤► RRF 融合 ► bge-reranker 精排
                                               │            │
                                               ▼            ▼
                                          引用溯源 ◄──── LLM 生成（云 API）
```

- 检索组件（embedding / rerank）本地 GPU 推理，生成走云 API（DeepSeek/Qwen/GLM），
  控制成本的同时保证答案质量——这是生产环境的典型混合架构

## 评测（项目的灵魂）

自建 golden set（目标 300 条），指标：检索 Top-K 召回率 / MRR、答案忠实度、数字准确率。
所有优化（切分策略、混合检索、rerank、查询改写）必须有前后对比数据，记录在
`docs/eval-report.md`。

| 版本 | 变更 | Top5 召回率 | 忠实度 |
|------|------|------------|--------|
| v0 naive baseline | 固定 chunk + 纯向量 | 待测 | 待测 |
